# Prompt-to-Production Note (debrief.md)

## 1. Which AI output misled you most?

The CSV import idempotency logic generated by Claude was the most misleading. The AI generated a `bulkUpsertRecords` function that used an upsert (INSERT OR UPDATE) operation, which looked correct at first glance. However, the import summary always reported all rows as "imported" — even when uploading the same file multiple times. The AI never implemented the check to distinguish between newly inserted records and already-existing ones. This meant the idempotency requirement appeared to work (no duplicates were created) but the response was lying — it always said "55 imported, 0 skipped" instead of "0 imported, 55 skipped" on the second upload.

## 2. How did you identify the issue?

The issue was identified by manually testing the idempotency requirement — uploading the same CSV file twice and checking the import summary both times. Both uploads reported "55 imported, 0 skipped, 0 errors", which was clearly wrong. A correct idempotent import should report "0 imported, 55 skipped" on the second upload. Tracing the code revealed that `results.imported = valid.length` was set unconditionally after the upsert, without checking whether each record already existed before insertion.

## 3. What did you verify manually?

- Uploaded the same CSV file twice to verify idempotency — confirmed the fix worked after adding a pre-insert existence check
- Opened two browser tabs on the same attendance session and saved from both to trigger a version conflict — confirmed the ConflictResolver modal appeared with all 3 options (Reload Latest, Retry Update, Compare Changes)
- Tested the faculty tripwire by attempting to mark attendance for a session not assigned to the logged-in faculty — confirmed the server rejected with 403 and the UI showed a meaningful error
- Verified the `/metrics` endpoint via browser console with a valid admin token — confirmed count, avg_ms, and p95_ms were returned for all tracked operations
- Checked that students below 75% attendance were flagged with warning badges in the Admin dashboard
- Refreshed the attendance sheet mid-edit to verify draft recovery restored unsaved changes automatically

## 4. What would you improve if given another day?

- **Persistent metrics**: The current `/metrics` endpoint uses an in-memory tracker that resets on server restart. I would integrate a proper metrics store (Redis or a time-series DB) so metrics survive restarts and can show historical trends.
- **Admin CSV import**: Currently only faculty can import attendance CSV, restricted to their assigned sessions. I would add a dedicated Admin import page that bypasses faculty assignment checks, allowing bulk import across all sessions and departments.
- **Better conflict UI**: The current ConflictResolver shows the conflict at the bulk level. I would improve it to highlight exactly which student record caused the conflict in the attendance sheet, making it easier for faculty to resolve.
- **Email delivery robustness**: Email alerts to parents are working end-to-end via SMTP. I would add a retry queue (e.g., BullMQ + Redis) so transient SMTP failures don't silently drop notifications, and add a delivery status log so admins can see which alerts were sent successfully.
- **End-to-end tests**: I would add Playwright or Cypress UI tests to automate the conflict resolution flow and the faculty tripwire scenario, rather than relying on manual testing for these critical paths.
